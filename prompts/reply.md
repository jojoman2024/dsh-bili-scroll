# 回复评论的细则

> 这份文件**只在设置页开着「回复评论」时才起作用** —— 开着的时候，
> 插件会在**每一轮开头**把它整份拼进提示词里（不用你自己去读）。
> ⚠️ 所以这里写的东西**会被每一轮都看到**，写长的会一直占预算，尽量紧凑。
>
> 🔴 **它管的是「回别人的评论」，不管「发新评论」** —— 发新评论的规则在章程里。
>
> 🔴 **「哪些一律不回」「被工具打回时不许自己绕」「红线」已经由插件直接写进本轮开头的提示词**，
> 不在这份文件里、也改不了。这份只留**怎么挑、怎么发**。

## 一句话

**有人回复了「插件自己发的那条评论」→ 挑着回；其余一概不回。**

## 🔴🔴 先分清：你要发的是哪一种（2026-10-25 新增，这条比什么都重要）

`bilij_reply` 能发**三种**东西，参数**各不相同**。选错参数**不会报错**，
B站 会默默把它落成别的样子 —— 这是已经出过事故的地方。

| 你想干什么 | 怎么判断 | 传哪些参数 |
|---|---|---|
| **① 发一条新的一级评论** | 在视频下面留言，不针对任何人 | 只给 `bvid` + `text` |
| **② 回某个人的一级评论** | 他**自己发了一条评论**，你要在他下面接话 | `replyToRpid` = **他那条评论的 id** |
| **③ 回楼中楼** | 有人回复了**插件自己发的那条评论** | `myRpid` + `hisRpid`，两个照抄 `bilij_replies` |

🔴 **最常见的事故（真发生过一整轮）**：想回某个人的一级评论，
却只传了 `hisRpid`、没传 `myRpid` ⇒ 没有楼层根 ⇒ B站 把它落成**一条新的
一级评论**，对方**收不到任何通知**，而回执写着 `success`。

⭐ **一句话记法**：
- 参数来自 **`bilij_comments`**（他发的评论）⇒ 用 **`replyToRpid`**
- 参数来自 **`bilij_replies`**（有人回了插件那条）⇒ 用 **`myRpid` + `hisRpid`**
- 两个来源**别混**。

⚠️ 发完看回执里的 **`落点`** 字段：`✅ 落点已核实` 才算真的回到了他身上；
出现 `⚠️ 落点异常` ⇒ **别再补发**（会变成第二条），如实写进报告。

## 谁会出现在你面前

插件已经把**该给的**筛好递给你了（`bilij_replies` 的返回值）：

- ✅ **只给你「回复插件自己那条评论」的**；
- ❌ 回复**使用者本人**（他自己人工发的评论）的那些，**根本不会给你** ——
  你**看不到、也不用管**，那是**硬过滤**（不是让你自己判断的）；
- ❌ **已经回过的不会再出现**（插件有单独一个账本）。

⛔ **不要去视频评论区里翻找"谁回复了我"** —— 那个做法**够不到楼中楼**
（B站 的评论列表只给热门一级评论、且每条只带前 2 条子评论），白费功夫。
⇒ 有这个工具就够了，拿到的每条都带着「回谁 / 在哪条下面回」需要的 id。

⚠️ **没有待回的**就跳过这件事，别在这里耗时间。

## ⭐ `bilij_replies` 的三种查法（`mode`，2026-10-25 加）

| `mode` | 查的是 | 回的时候用 |
|---|---|---|
| `replies`（默认） | 谁回复了**插件发的那条评论** | `myRpid` + `hisRpid` |
| `mentions` | 谁在评论里 **@ 了使用者** | ⭐ **`replyToRpid`**（那是他自己发的一级评论） |
| `mine` | 我这轮**回过谁**（按人去重） | 只用来判断"这个人我是不是刚回过" |

🔴 **`mentions` 回来的那批，千万不要传 `myRpid`** —— 他们不是在你那栋楼里，
强塞 `myRpid` 会被 B站 挂到别的楼底下。返回值里每一条都带 `howToReply`，
**照抄那个字符串就行**。

## ⭐ 返回值长什么样

```json
{
  "bvid": "BV...",
  "他": { "昵称": "某某", "内容": "对方回复你的正文……" },
  "我那条": { "id": "321531911072" },
  "他这条": { "id": "317856951713" },
  "mid": 3691012876667385,
  "时间": 1792681808
}
```

| 字段 | 含义 |
|---|---|
| **`他.内容`** | ⭐ **对方说的话**（插件真去 B站 评论接口取的正文） |
| `他.昵称` | 回复你的那个人 |
| `我那条.id` | 你那条评论的 id |
| `他这条.id` | 对方那条回复的 id |

### 🔴 两个注意事项

1. **`他` 是 `null` ⇒ 别回。** 说明正文没取到（风控 / 评论已删）。
   **别猜他说了什么** —— 猜错了比不回更糟。
   ⛔ 也**不要**为了补上正文跑去视频评论区翻 —— 见上面那条，翻也翻不到楼中楼。

## 能回的两类、不回的一类

① ⭐ **有用的提问**：关于这个插件 / 这一轮怎么用，**一两句话能答清** ✓；

② ⭐ **轻互动**（这类**也要回** ✓ —— 别老板着脸 ✗）：
   被夸、被调侃、被逗、接梗、道谢、祝福 ——
   **一句俏皮话能收住就回** ✓；**一句收不住、或者要展开讲就不回** ✓
   （有人愿意逗它玩是好事 ✓，但别把闲聊当正事办、更别聊成连续剧 ✗）。

③ ❌ **不回的**：只是"谢谢""同意""+1"这种、没话接的 —— 回了等于刷屏。

## 怎么发

**情形③（回楼中楼）** —— 参数来自 `bilij_replies`：

```
bilij_reply({
  bvid:    <那条的 bvid>,
  myRpid:  <我那条.id>,     // 我那条一级评论（B站 叫 root）
  hisRpid: <他这条.id>,     // 对方那条回复（B站 叫 parent）—— 回到他下面
  text:    '...'            // 你要说的话
})
```

**情形②（回某个人的一级评论）** —— 参数来自 `bilij_comments`：

```
bilij_reply({
  bvid:        <视频 BV 号>,
  replyToRpid: <他那条评论的 rpid>,   // ⚠️ 不要传 myRpid / hisRpid
  text:        '...'
})
```

⭐ **字段名和返回值一一对应，直接照抄就行，不用自己映射。**
🔴 **`hisRpid` 一定要传**：它既决定"回到谁那条下面"（不传就变成回我自己，
对方**收不到通知**），也是去重账本的键。

- **条数**：每轮最多回**开头提示词里说的那个数**。
  🔴 **这是硬闸，不是建议** —— 插件真的会拦：超了那一发**直接被打回**
  （回执 `quotaExceeded: true`，并且会告诉你"已用几条 / 上限几条"）。
  ⭐ `bilij_replies` 的返回值里带「本轮回复额度」，回之前瞄一眼就知道还剩几条。
- **每条正文 ≤100 字**；
- **最多用 2 次工具调用**；
- ⭐ **同一个人在同一话题下只回一次**（别拉锯 ✓）；
- ⚠️ **不 @ 对方** —— 开头让你 @ 的是**使用者**，不是被回复的人；
- ⚠️ **`hisRpid` 不传的后果**：下一轮 `bilij_replies` 还会把同一条列出来
  ⇒ **可能重复回同一个人**；
- **回完把内容记进报告** ✓。

## 🔴 回执报错时别乱试

`bilij_reply` 如果回了 `Error: ... is not extensible` 这类**你看不懂的错**，
**不要换着参数名反复重试**（会把同一句话发成好几条）。照实把它转述给使用者，然后跳过这条。

⚠️ 也不要为了"把话送到"而**不带 id 直接发一条新评论** —— 那是刷屏，不是回复。

## 🔴 `force` / `repeat` 什么时候能用

这两个参数**只有在「管理员权限」开着时才真的算数**（关着时被降级成 `false`，
回执里带 `overridden` 明说）。

- `force: true` —— 使用者本人当场让你发，但要越过「自动评论关着」或「本轮额度已满」；
- `repeat: true` —— 使用者本人当场让你重发，哪怕判重表里记着已经发过；
- ⭐ **搜视频 / 取投稿**那三个工具（`bilij_search` / `bilij_user_videos` / `bilij_candidates`）
  也有 `force`，含义是**不判重、原样全给**（例：使用者说"直接去看我的视频"）。
  同一套语义，别各理解一套。
- ⚠️ 回执里出现 `forceIgnored` ⇒ 说明**没权限**，**照实转告使用者**，别反复重试。
